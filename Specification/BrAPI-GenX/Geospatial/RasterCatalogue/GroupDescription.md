# Group RasterCatalogue

**Status:** BrAPI-GenX **STRUCTURAL_DRAFT** candidate under Request for Comments (RFC) 144. `RasterCatalogue` proposes descriptive discovery metadata, not an accessible raster image, verified georeferenced data cube, computational tile service, or scientifically validated vegetation-index measurement.

The registration request requires only `rasterCatalogueDbId`; the response additionally requires lifecycle `status`. `datasetName`, `datasetType`, `resolution`, `crs` (coordinate reference system), `extent`, `supersedes` and `provenance` are all optional. Dataset type and spatial descriptors are unconstrained strings, not standard code lists or verified coordinate geometries. No raster file location, image/dataset identifier link, band inventory, geotransform, value type, unit, no-data code, pixel dimensions, cloud-quality flag, content digest, access/license constraints, or calibration metadata is represented. `NDVI` (normalized difference vegetation index) is an illustrative dataset-type label, not a measured or calibrated value.

**Official-contract overlap:** Official BrAPI version 2.1 already defines an `Image` metadata/request resource with an `imageURL`, image dimensions, timestamp and geolocation. This is not equivalent to a scientific raster catalogue, but it makes a blanket claim that BrAPI lacks image/dataset metadata misleading. No source contract supplies a verified crosswalk between this draft, official Image or GenX RemoteSensingMetadata/CloudMask. A catalogue entry cannot demonstrate that a raster can be retrieved or analyzed.

**Deferred design decisions:** D-430 asks whether `extent` should be required (currently optional); D-431 whether `datasetType` should be controlled (currently free text); D-432 whether there should be a GenX `ResearchAsset` link (none is modelled). All remain unratified.
