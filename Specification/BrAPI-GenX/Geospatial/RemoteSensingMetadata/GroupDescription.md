# Group RemoteSensingMetadata

**Status:** BrAPI-GenX **STRUCTURAL_DRAFT** candidate under Request for Comments (RFC) 145. `RemoteSensingMetadata` proposes a discovery-level sensor/platform metadata record, not a calibrated image product, orthorectified raster, reliable geospatial observation, or an official Breeding Application Programming Interface (BrAPI) version 2.1 field-phenotype record.

The registration request requires **only** `remoteSensingMetadataDbId`; the response additionally requires lifecycle `status`. `platform`, `sensor`, `acquisitionDate`, `crs` (coordinate reference system), `resolution`, and `provenance` are optional. They are free-text strings or an optional referenced provenance object. `acquisitionDate` has no enforced date format, `crs` no validated spatial reference identifier, and `resolution` no structured unit or value constraint. No image/raster source reference, footprint, spectral band identification, geometric error, radiometric calibration, cloud mask, atmospheric correction or acquisition timestamp is required.

**Scientific and geospatial boundary:** Example platform and sensor labels are not proof of a particular instrument, reproducible acquisition or spatial accuracy. An optional resolution and coordinate reference string cannot establish georeferencing, co-registration, temporally aligned pixels or comparable derived indices. The related draft `VegetationIndex` also lacks a numerical index and source-raster reference; do not infer that a metadata-only record supplies these. D-433–D-435 remain deferred, with no `researchAssetDbId` link modelled.
