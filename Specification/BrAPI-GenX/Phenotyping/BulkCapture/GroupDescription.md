# Group BulkCapture

**Status:** BrAPI-GenX **STRUCTURAL_DRAFT** candidate under Request for Comments (RFC) 040. This proposes an immutable *batch-capture event envelope*, not a replacement for official Breeding Application Programming Interface (BrAPI) version 2.1 Observations, proof of transactionally submitted measurements, or a production-ready field-data collection workflow.

The registration request requires `bulkCaptureDbId`, `studyDbId`, date-time formatted `capturedAt`, and an `entries` array; the response additionally requires lifecycle `status`. The `entries` array has **no `minItems`**, so even an empty batch satisfies this portion of the schema. Each entry requires only a string `variableDbId`; `observationUnitDbId`, nullable numeric `value`, `unit`, and `qualityFlag` are optional. `qualityFlag` has an enum (`valid`, `suspect`, `invalid`, `missing`) but is **not required**. There is no entry-level missing reason, categorical value, validated unit scale, observation identifier, field-book reference, authoritative Study/ObservationUnit join, per-entry timestamp, or conditional rule reconciling flags with missing values.

**Official-contract overlap:** Official BrAPI v2.1 `POST /observations` already accepts an **array** of `ObservationNewRequest` entries; it is incorrect to suggest official BrAPI lacks bulk observation submission. The official request's nullable `value` is a **string**, whereas GenX BulkCapture's optional numeric `value` cannot express categorical observations. No contract specifies atomic creation of official Observations, a durable handoff of each captured entry, a mapping from `variableDbId` to official `observationVariableDbId`, authorization across authorities, or successful error/partial-failure handling. An event record is not a complete phenotyping dataset.

**Deferred design decisions:** D-118 asks whether a nonempty `entries` array should be required (currently no minimum); D-119 asks about linking GenX `PhenotypeCapture` (there is no modelled `phenotypeCaptureDbId`); D-120 asks about a FieldBook link (no `fieldBookDbId` is modelled). These are open questions, not optional relationships already implemented.
