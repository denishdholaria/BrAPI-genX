# Group PopulationAdvancement

**Status:** BrAPI-GenX **STRUCTURAL_DRAFT** candidate under Request for Comments (RFC) 035. This proposed record represents an *actual population-progression event*, not a permitted scheme transition definition, planned cross, authorized breeding-selection verdict or verified material inventory transaction. Decision D-BP-10 preserves this distinction.

The registration request requires `populationAdvancementDbId`, authority-qualified `programReference` and `populationReference` objects, and `advancedAt` (date format). The response additionally requires lifecycle `status`. `pipelineContext`, `schemeContext`, `notes`, and `provenance` are optional. When a scheme context is supplied, `fromStageId` and `toStageId` are nested inside the exact `BreedingSchemeVersion` context; neither stage may be invented as a free-standing global field. The pipeline revision is an optional separate binding. This event must not mutate the immutable permitted-transition graph.

**Identity and execution boundary:** Authority-qualified BrAPI Program and population/family references preserve the owning server and resource type, but storing a candidate event does not independently prove that physical materials moved, that external ownership checks succeeded, or that a breeding selection was formally authorized. No universal mapping from population/family to Germplasm has been approved. The distinct `SelectionDecision` contract describes a verdict rather than material movement. D-102–D-104 remain deferred. The `CrossingSchedule` proposal remains deferred by D-BP-11; this review does not activate it. Draft immutable replay is not evidence of deployed persistence.
