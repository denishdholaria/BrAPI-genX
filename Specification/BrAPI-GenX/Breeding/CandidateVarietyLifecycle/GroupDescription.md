# Group CandidateVarietyLifecycle

**Status:** BrAPI-GenX **STRUCTURAL_DRAFT** candidate under Request for Comments (RFC) 039. `CandidateVariety` proposes a local candidate-lifecycle metadata record, **not** a legal variety registration certificate, statutory release, seed-sale authorization, cultivar identity verification, or an official Breeding Application Programming Interface (BrAPI) version 2.1 variety registry.

The registration request requires `candidateVarietyDbId`, `programDbId`, and `varietyName`; the response additionally requires `status`. The request `status` defaults to `candidate`. The status vocabulary includes `submitted`, `registered`, and `released` as **self-reported candidate labels**, but the schema does not require registration authority, notification identifier, official decision date, jurisdiction, legal evidence, certificate, validated germplasm reference or status-transition authorization. `registeredAt` is optional even when status is `registered`, and `programDbId` is a plain string rather than an authority-checked Program reference.

**Governance boundary:** A stored `released` value or `registeredAt` date does not prove national/state-level approval, cultivar notification, compliance, seed certification, or release into commerce. A candidate name is not a validated unique variety denomination. No `germplasmDbId` or `breedingPipelineDbId` linkage is modelled; external Germplasm identities remain authoritative. D-115–D-117 remain open, including event-based status transitions and the conditions for `registeredAt`. A `PopulationAdvancement` event or `SelectionDecision` verdict is not automatically an authorization to release a variety. Draft immutable replay is not independently verified service behavior.
